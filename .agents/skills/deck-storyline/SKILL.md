# Deck Storyline

Start with the end in mind. Use the brief and existing deck or artifacts where available; ad-hoc work does not require creating workflow artifacts. Infer reasonable working assumptions and ask only when a consequential uncertainty blocks the task.

- **Outcome first.** Identify the primary thing the audience should do, believe, or know. Use an observable success signal when useful and available.
- **Problem.** Identify any obstacle between the audience and the outcome.
- **Audience.** Consider their understanding, questions, stakes, and decision power where relevant; mark unknowns rather than inventing facts.
- **Class fit.** When planning a deck or using an established class, use `deck-structure`'s criteria at `../deck-structure/SKILL.md` and read the selected `../deck-structure/classes/<class>.md` for its structure. An ad-hoc edit can follow the brief and existing deck without choosing a class or restructuring it.
- **Evidence.** Carry sources through to factual claims; mark missing evidence as `gap`. Desired outcomes and ceremonial labels need no invented evidence.
- **Order.** Make the structure's dependencies clear; when using a class guide, preserve its dependencies. Each content slide makes one point; apply `deck-slide-rules`.
- **Pacing.** Match the sequence to the delivery mode, available time, and reading density. Estimate timing when a time budget applies.
