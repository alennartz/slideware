# Deck Tooling

The repo's commands and file rules.

## Source and output

- `decks/<slug>/source/slides.html` is the slide source. Edit it and assets in `decks/<slug>/source/assets/`.
- `decks/<slug>/output/<slug>.html` is the published deck, generated by the build. Never edit it.
- Store PDF exports in `decks/<slug>/output/<slug>.pdf`.
- The engine's edit view saves over the published HTML file. Do not use it on factory decks.

## Commands (repo root)

- Build one deck: `make build SLUG=<slug>`. Build all: `make build`.
- Foreground preview: `make preview SLUG=<slug> PORT=<port>` (default 4321). Background lifecycle below.
- Tests: `make test`. Offline diagram browser smoke test: `make test-browser` (requires installed `agent-browser` and Chromium). List decks: `make decks`.
- External add-ons: `make addons` lists configured themes and commands; `make assets ADDON=<id> ARGS='<command>'` runs a listed asset command explicitly.

Build failures print the reason and exit non-zero. Read the message before retrying.
Build and library details: `build/README.md`, relative to the repo root.

## Background preview

Use the canonical absolute repo path (`pwd -P` from the repo root) as `<repo>`.
Namespace state by that path: `/tmp/slideware<repo>/dev-<slug>.{pid,url,log}`.
For example, repo `/workspace/slideware` uses
`/tmp/slideware/workspace/slideware/dev-foo.pid` for slug `foo`.
Only manage state in this repo's namespace; still verify process identity.

1. **Find or reuse.** Read the saved PID, then inspect `ps -p <pid> -o args=`.
   Verify a direct Node invocation of this repo's absolute `preview/dev.mjs`
   path and this exact slug, including argument boundaries. A live PID alone
   is not enough. If the PID is missing, dead, or belongs to another process,
   discard this namespace's stale PID/URL state without killing that process. Inspect
   `ps ax -o pid=,args=` for a matching preview before starting another; recover
   its PID if there is exactly one match. Resolve multiple matches explicitly.
   Read the saved URL, or recover it from `previewing <slug> at <url>` in the
   log from that process's launch, not an older or another repo's log. Check
   that its port agrees with the verified process (for port 0, use the logged
   assigned port), and that the URL serves the deck. Save any recovered PID
   and actual URL. Reuse only after those checks; if the URL cannot be verified, investigate
   rather than guessing it or launching a duplicate.
2. **Start if none exists.** Use port 4321 if free, another free port, or port 0
   to let the server choose. Run these lines in the same shell invocation:

   ```sh
   mkdir -p "/tmp/slideware<repo>"
   node "<repo>/preview/dev.mjs" "<slug>" "<port>" > "/tmp/slideware<repo>/dev-<slug>.log" 2>&1 &
   printf '%s\n' "$!" > "/tmp/slideware<repo>/dev-<slug>.pid"
   ```

   Keep the Node launch separate from `&&` chains so `$!` identifies Node,
   not a background shell. Wait for `previewing <slug> at <url>` in the new
   log, verify the saved PID's repo and slug as above, then check the URL.
   Save that actual URL in `/tmp/slideware<repo>/dev-<slug>.url`; never infer it from a default
   port. An exited process, build error, or bind error before the success line
   is a startup failure, not a reusable preview. Read the log, clear failed
   PID/URL state, and fix the cause before retrying.
3. **Stop.** Recheck the saved PID's repo and slug immediately before
   `kill <verified-pid>`. Once it exits, remove its PID and URL files. A missing,
   dead, or mismatched PID is stale state: remove the state, not the unrelated
   process. If the matching preview still runs under another PID, recover and
   verify that PID before stopping it.
